# Security policy

## Supported versions

Security reports are reviewed for the latest code on the repository's default branch and the currently published Table Games release. Older releases and modified copies are not supported. This policy does not promise response deadlines or grant rights to modify or redistribute the proprietary source.

## Report a vulnerability privately

Use GitHub's **Report a vulnerability** option on the repository's Security tab, or [open a private vulnerability report](https://github.com/ghost-ng/Table-Games/security/advisories/new). See GitHub's instructions for [privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/privately-reporting-a-security-vulnerability).

Include the affected version or commit, reproduction steps, expected and observed behavior, impact, and a minimal example with sensitive data removed. Keep disclosure private while the report is investigated and a fix or mitigation is coordinated.

Do not post credentials, tokens, private keys, personal data, or exploit details in public issues or discussions. If a credential was exposed, revoke or rotate it through its provider; remove the actual value from any report. No email address or other private contact channel is published by this policy.

If GitHub's private reporting option is unavailable, do not move sensitive details into a public issue. GitHub documents that repository owners must enable this feature; use the private report once it is available.
