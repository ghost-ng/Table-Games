# Game art fidelity and production QA

Verified 2026-09-27 against the production web export at `http://localhost:4179/`, using Chrome for Testing 154.0.8037.0 (Chromium) and Linux Node 22. Browser plugin not available; the installed Playwright CLI drove the browser. No browser or application dependency was added.

The visual direction is defined by the [Modern](references/modern-game-art-direction.webp), [Retro](references/retro-game-art-direction.webp), and [Arcade](references/arcade-game-art-direction.webp) reference sheets. All three sheets were viewed directly alongside fresh application captures. These are material references, not fixed UI compositions. [Production provenance](game-art-production.md) records the 117 local WebP cutouts.

## Responsive and Home-card measurements

The complete matrix contains all fourteen game/tool routes × three themes × `320×740`, `390×844`, `430×932`, and `1440×1000`: **168 cases**, including 42 phone captures at `390×844` and 42 desktop captures. All 132 rendered `game-board` elements fit within the viewport. Document scroll width equals viewport width in every case.

| Portrait viewport | Ten full-width board routes, every theme | Horizontal bounds | Mancala width, Modern / Retro / Arcade |
| --- | --- | --- | --- |
| 320×740 | 296px | x=12, right=308 | 121 / 124 / 119px |
| 390×844 | 366px | x=12, right=378 | 175 / 174 / 173px |
| 430×932 | 406px | x=12, right=418 | 202 / 201 / 201px |

The ten routes are Tic Tac Toe, Four in a Row, Checkers, Dots & Boxes, Chinese Checkers, Pop & Race, Word Search, Crossword, Word Grid, and Word Guess. All **90 full-width phone assertions** have zero width error, inside the allowed 2px tolerance. Hangman, Coin Flip and Dice are content surfaces without a `game-board` root and are checked for document/image bounds instead.

Mancala uses its preserved vertical `8.4 / 2.6` aspect ratio on phones. A full-width board would need approximately 956, 1182 or 1312px of board height before headers and controls; the tested phone heights cannot provide that. Its measured board heights are 384–401, 559–565 and 649–653px, retaining the stores, pits, count labels and Rematch. This is the intended vertical-fit exception, not a nested-gutter failure. Desktop Mancala is horizontal at 1000px wide. Compact landscape tactile-game checks at `844×390` also fit.

Home tools remain two adjacent icon-and-name cards on phones. Game, Coin Flip and Dice cards all measure **136 / 171 / 191px** at viewport widths **320 / 390 / 430**; desktop cards measure **260px**. Tool cards are 112px tall, have 48×48px art, share a row, and keep the same 16px grid gap. No tool becomes a full-width list row. Theme picker, mode dialog, result dialog, navigation and keyboard activation were exercised.

## Gameplay, local assets and offline evidence

Real interactions cover selected/legal pieces, a ten-move checker promotion, claimed boxes and last-edge markers, a marble move, Mancala sowing, four-seat race play, found Word Search paths, Crossword entry, Word Grid path/undo, Word Guess duplicate-letter evaluation, winning rows, result dialogs, rematch, coin outcomes and die holds. All six die types were tested at values 1 and their side count. Active representative rounds retain board labels, scores, guesses, paths, ownership, held state and history through Modern → Retro → Arcade switches. Game routes do not expose a theme picker, so this particular in-round check invokes the existing theme-provider setter from the browser; it never writes game state or modifies application source. Moves themselves use actual controls.

Offline testing used a fresh browser context that visited **only Home while online**. Service-worker readiness and control were awaited; cache `table-games-f0bd8e1680b2` contained all **175 exported files**, including **117 themed piece assets**. Playwright then set the context offline. Home, Checkers and Hangman were navigated to and reloaded in each theme, with `navigator.onLine === false` and an active controller. All nine cases rendered meaningful UI; Checkers selection and Hangman guessing remained interactive. Home loaded 15 images, Checkers 26, and Hangman 2; every image decoded. Every recorded reload response was HTTP 200 from the service worker, and there were no external requests, application console errors or framework overlays.

The manifest parses without errors, declares standalone display, scoped start URL, 192px and 512px icons, and a maskable icon. Chromium's installability inspection reported only `in-incognito` for the automation contexts. An OS-level installation and native home-screen launch were not performed; real browser offline reload and cache completeness were verified. Font-license/PWA tests also cover root and `/Table-Games` base paths.

## Correction and verification

The initial clean `verify:all` passed 18 WSL checks, 76 application unit checks, four asset checks, TypeScript and production export. The separate normal `check:public` correctly failed because two internal planning documents were tracked under `docs/superpowers/`. Complete byte-identical copies were preserved in ignored QA scratch, and only those two tracked documents were removed. The normal public-readiness gate then passed, as did all 54 public/license regression tests. Accepted reference sheets, production provenance and application files were retained. No game, art, layout, dependency or service-worker implementation needed a Task 9 correction.

Final fresh `npm run clean && npm run verify:all && npm run check:public` completed with exit 0 after the correction: 18/18 WSL, 76/76 unit, 4/4 asset checks, typecheck, production export and normal public-readiness gate passed. The regenerated PWA hash remained `f0bd8e1680b2`, matching the artifact exercised by the browser.

Browser test harness issues were corrected before accepting results: a blocked Crossword-cell selector, an interrupted CLI operation that overlapped a later run, browser Request URL property usage, a competing installability CDP session that had to be detached before offline emulation, and a CLI-global URL-constructor assumption. The complete matrix was rerun in a clean browser session. These were test-environment issues, not application fixes.
